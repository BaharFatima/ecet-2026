📌 Number Systems & Conversions

Number System Bases
Binary (Base 2): digits 0,1 Octal (Base 8): digits 0–7 Decimal (Base 10): digits 0–9 Hexadecimal (Base 16): digits 0–9, A(10), B(11), C(12), D(13), E(14), F(15)
Decimal → Binary (Divide by 2, read remainders upward)
  1. Divide decimal number by 2, note remainder
  2. Continue dividing quotient by 2 until quotient = 0
  3. Read remainders from BOTTOM to TOP = binary representation
Conversion Examples

Decimal 45 → Binary: 45÷2=22 R1; 22÷2=11 R0; 11÷2=5 R1; 5÷2=2 R1; 2÷2=1 R0; 1÷2=0 R1 Read remainders bottom-up: 101101₂ ✓ Binary 110101 → Decimal: 1×2⁵+1×2⁴+0×2³+1×2²+0×2¹+1×2⁰ = 32+16+0+4+0+1 = 53 Hex 2F → Decimal: 2×16 + F×1 = 32+15 = 47 Decimal 255 → Hex: 255÷16=15 R15(F) → 15÷16=0 R15(F) → FF

📌 Binary Codes

BCD (Binary Coded Decimal): each decimal digit represented by 4-bit binary Decimal 97 → BCD: 1001 0111 (9→1001, 7→0111) Gray Code: only ONE bit changes between consecutive values Useful to avoid errors during transitions (shaft encoders) Decimal→Gray: MSB same; each other bit = XOR of binary's consecutive bits Binary 0101 → Gray: 0, 0⊕1=1, 1⊕0=1, 0⊕1=1 → 0111 ASCII: 7-bit code for characters (128 combinations) 'A'=65(41H), 'a'=97(61H), '0'=48(30H) Excess-3 Code: BCD + 3 (self-complementing code) Decimal 5 → BCD 0101 → Excess-3: 0101+0011=1000

📌 Logic Gates — Truth Tables & Symbols

All Basic Gates
AND: Y = A·B (Y=1 only when ALL inputs=1) OR: Y = A+B (Y=1 when ANY input=1) NOT: Y = Ā (inverts: 0→1, 1→0) NAND: Y = (A·B)' = Ā+B̄ (AND + NOT; universal gate) NOR: Y = (A+B)' = Ā·B̄ (OR + NOT; universal gate) XOR: Y = A⊕B = AB̄+ĀB (Y=1 when inputs are DIFFERENT) XNOR: Y = (A⊕B)' = AB+ĀB̄ (Y=1 when inputs are SAME = equality checker)
💡

Universal gates: NAND and NOR are "universal" — any logic function can be built using ONLY NAND gates (or only NOR gates). This is used in practice for chip cost reduction.

📌 Boolean Algebra & De Morgan's Theorems

Basic Laws: Idempotent: A+A=A; A·A=A Identity: A+0=A; A·1=A Complement: A+Ā=1; A·Ā=0 Dominance: A+1=1; A·0=0 Involution: (Ā)' = A (double negation) Commutative: A+B=B+A; A·B=B·A Associative: A+(B+C)=(A+B)+C; A(BC)=(AB)C Distributive: A(B+C)=AB+AC; A+BC=(A+B)(A+C) Absorption: A+AB=A; A(A+B)=A De Morgan's Theorems (critical!): (A+B)' = Ā·B̄ [NOR = AND of complements] (A·B)' = Ā+B̄ [NAND = OR of complements] Extension: (A+B+C)' = Ā·B̄·C̄ (A·B·C)' = Ā+B̄+C̄ Memory: "Break the line, change the sign" → complement the whole expression, complement each variable, change + to · (or vice versa)

📌 SOP, POS & Karnaugh Maps (K-Maps)

SOP (Sum of Products): ORing of AND terms (minterms) e.g., F = AB + ĀC + BC → three AND terms ORed together POS (Product of Sums): ANDing of OR terms (maxterms) e.g., F = (A+B)(Ā+C)(B+C) Minterm: product term where ALL variables appear (either complemented or not) Maxterm: sum term where ALL variables appear K-Map Method (for minimization up to 4 variables): Arrange truth table output in Gray code order in a grid. Group adjacent 1s in groups of 1,2,4,8 (powers of 2). Groups can wrap around edges and corners. Larger groups = simpler expression. Variables that change within a group are eliminated; those that remain form the product term. 2-variable K-map: 2×2 grid 3-variable K-map: 2×4 grid (rows: 00,01,10,11 in Gray order: 00,01,11,10) 4-variable K-map: 4×4 grid
K-Map Example — 3 Variables

F(A,B,C) = Σm(1,3,5,7) — four minterms, all where C=1 K-map: BC AB: 00 01 11 10 0: 0 1 1 0 1: 0 1 1 0 The four 1s (m1,m3,m5,m7) form one group of 4 → C=1 throughout, A and B both change → eliminate A and B Simplified: F = C (just the variable C!)

📌 Combinational Circuits

Half Adder: Adds two 1-bit numbers (A,B). No carry input. Sum S = A⊕B (XOR) Carry C = A·B (AND) Full Adder: Adds three bits (A,B,Cin). Has carry-in. Sum S = A⊕B⊕Cin Cout = AB + Cin(A⊕B) Built from two half adders + OR gate. Multiplexer (MUX): Data selector — selects one of 2ⁿ inputs based on n select lines. 4:1 MUX has 4 data inputs, 1 output, 2 select lines. Y = S₁'S₀'·I₀ + S₁'S₀·I₁ + S₁S₀'·I₂ + S₁S₀·I₃ Demultiplexer (DEMUX): 1 input → one of 2ⁿ outputs based on n select lines. Inverse of MUX. Encoder: 2ⁿ inputs → n-bit binary output (e.g., 8:3 priority encoder) Decoder: n-bit input → 2ⁿ outputs (e.g., 2:4 decoder, 3:8 decoder) Used in memory addressing. Comparator: compares two n-bit numbers A and B. Outputs: A>B, A=B, A

📌 Sequential Circuits — Flip-Flops

Latches vs Flip-Flops: Latch: level-triggered (transparent while clock=1) Flip-Flop: edge-triggered (changes only on clock edge) SR Flip-Flop: Set-Reset S=0,R=0: No change (Q unchanged) S=1,R=0: Set (Q=1) S=0,R=1: Reset (Q=0) S=1,R=1: INVALID/forbidden state (indeterminate) D Flip-Flop: Data/Delay On clock edge: Q = D (output follows input) Used for data storage, shift registers. JK Flip-Flop: Solves SR's invalid state J=0,K=0: No change J=1,K=0: Set (Q=1) J=0,K=1: Reset (Q=0) J=1,K=1: TOGGLE (Q flips to Q') ← this is the improvement over SR T Flip-Flop: Toggle T=0: No change; T=1: Toggle (Q→Q') Made from JK with J=K=T Used in counters.

📌 Registers & Counters

Register: group of flip-flops storing n bits SISO (Serial In, Serial Out): data shifts one bit per clock SIPO (Serial In, Parallel Out): serial input, all bits available in parallel PISO (Parallel In, Serial Out): parallel load, serial output PIPO (Parallel In, Parallel Out): parallel load and read (fastest) Counters: Ripple (Asynchronous): each FF clocked by output of previous. Simple but slow. Synchronous: all FFs clocked simultaneously. Faster, more complex. Up-counter: counts 0,1,2,...,2ⁿ−1,0,... Down-counter: counts 2ⁿ−1,...,1,0,2ⁿ−1,... MOD-N counter: counts from 0 to N-1 (N states) Memories: RAM (Random Access Memory): read/write, volatile, fast SRAM: flip-flop cells, fast, expensive (cache memory) DRAM: capacitor cells, needs refresh, cheaper (main memory) ROM: read-only, non-volatile Mask ROM, PROM, EPROM (UV-erasable), EEPROM, Flash ROM Flash ROM applications: USB drives, SSDs, memory cards, BIOS chips

📌 Functional Blocks of a Computer

1. Input Unit: accepts data from outside (keyboard, mouse, scanner) 2. Memory Unit: stores data and instructions - Primary: RAM, ROM (fast, directly accessed by CPU) - Secondary: HDD, SSD, DVD (slow, permanent storage) 3. ALU (Arithmetic Logic Unit): performs arithmetic (+,−,×,÷) and logic (AND,OR,NOT) 4. Control Unit (CU): fetches, decodes, executes instructions; coordinates all units 5. Output Unit: displays/sends processed results (monitor, printer) CPU = ALU + CU + Registers Stored Program Concept (Von Neumann): programs stored in memory like data, fetched and executed sequentially. Allows general-purpose computers.

📌 Number Representations

Fixed Point: decimal point at fixed position. Integer or fractional. Floating Point (IEEE 754): N = (−1)^S × M × 2^E S=sign bit, M=mantissa (fraction), E=exponent (with bias) Single precision: 1 sign + 8 exponent + 23 mantissa = 32 bits Double precision: 1+11+52 = 64 bits Complements: 1's complement of binary N: flip all bits (0→1, 1→0) e.g., 1's comp of 1010 = 0101 2's complement: 1's complement + 1 (used for signed integer arithmetic) e.g., 2's comp of 1010 = 0101+1 = 0110 Signed Representation: Sign-magnitude: MSB=0(positive), MSB=1(negative) 1's complement: positive normal; negative = 1's comp of positive 2's complement: most common; positive normal; negative = 2's comp of positive Range for n-bit: −2^(n-1) to 2^(n-1)−1 e.g., 8-bit: −128 to +127

📌 Instruction Formats & Addressing Modes

Instruction: OPCODE + ADDRESS(ES) Zero-address: operands on stack (e.g., PUSH, POP) → RISC architectures One-address: one operand, accumulator implied (classical CISC) Two-address: 2 operands, result in one of them (MOV AX, BX) Three-address: 2 source + 1 destination (RISC, e.g., ADD R1, R2, R3) Addressing Modes: Immediate: operand is constant in instruction ADD R1, #5 (5 is data) Direct/Absolute: address in instruction gives location of operand LOAD 1000 Indirect: instruction has address of address (pointer) LOAD @R1 (R1 holds address) Register: operand is in a CPU register ADD R1, R2 Register Indirect: register holds address of operand LOAD (R1) Indexed: EA = base address + index register LOAD 1000(R1) Relative: EA = PC + offset (used in branches/jumps) Base-register: EA = base register + offset (used for position-independent code)

📌 Memory Hierarchy

Hierarchy (fastest→slowest, most expensive→least): Registers → Cache (L1,L2,L3) → Main Memory (RAM) → Virtual Memory (Disk) Cache Memory: Sits between CPU and RAM. Stores frequently used data for fast access. Hit ratio h: fraction of accesses found in cache Effective access time: Teff = h×Tcache + (1−h)×TRAM Mapping: Direct Mapping: each RAM block → fixed cache line (simple, conflict misses) Associative: any RAM block → any cache line (best hit, complex hardware) Set-Associative: compromise — any block → one set, any line in that set Virtual Memory: disk acts as extension of RAM using paging/segmentation. Page Table maps virtual addresses to physical addresses. TLB (Translation Lookaside Buffer): fast cache for page table entries. Page Fault: page not in RAM → OS loads it from disk (slow!)

📌 I/O Modes & Parallel Processing

I/O Transfer Modes: Programmed I/O (Polling): CPU continuously checks if device is ready. Wastes CPU. Interrupt-driven I/O: Device interrupts CPU when ready. CPU does other work meanwhile. DMA (Direct Memory Access): DMA controller handles transfer; CPU free for computation. DMA is fastest for bulk transfers (disk, network, display). Pipelining: Divide instruction execution into stages. Different instructions in different stages simultaneously. Stages: Fetch → Decode → Execute → Write-back (4-stage example) Speedup: n instructions take (k+n−1) cycles vs n×k without pipeline (k=stages) Hazards: Data hazard, Control hazard (branches), Structural hazard Flynn's Classification: SISD: Single Instruction, Single Data → traditional uniprocessor SIMD: Single Instruction, Multiple Data → vector processor, GPU MISD: Multiple Instruction, Single Data → (rare, fault-tolerant systems) MIMD: Multiple Instruction, Multiple Data → multiprocessor, parallel computers RISC vs CISC: RISC: few simple instructions, fixed format, load-store architecture, many registers pipelining-friendly, compiler does more work. (ARM, MIPS) CISC: many complex instructions, variable length, memory-to-memory ops, fewer registers hardware does more work, code is denser. (x86, x86-64)

Asymptotic Notations: Big-O O(f(n)): upper bound (worst case) — "at most this slow" Omega Ω(f(n)): lower bound (best case) Theta Θ(f(n)): tight bound (average case) Common complexities (slow to fast): O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
Stack (LIFO — Last In, First Out): Operations: push(x), pop(), peek(), isEmpty() Implementation: array or linked list Applications: function call stack, undo operations, expression evaluation, balanced parentheses checking, DFS graph traversal Queue (FIFO — First In, First Out): Operations: enqueue(x), dequeue(), front(), isEmpty() Variations: Circular Queue, Deque (double-ended), Priority Queue Applications: BFS graph traversal, CPU scheduling, printer queue, breadth-first search

Trees: Binary Tree: each node has at most 2 children (left and right) Binary Search Tree (BST): Left subtree contains values < node Right subtree contains values > node Searching: O(log n) average, O(n) worst (degenerate) Tree Traversal: Inorder (L-Root-R): gives sorted order for BST Preorder (Root-L-R): useful for copying/serializing tree Postorder (L-R-Root): useful for deletion, expression trees Tree Terms: Root: top node (no parent) Leaf: node with no children Height: longest path from root to leaf Level: depth of a node (root is level 0 or 1)

📌 Sorting & Searching Algorithms

Bubble Sort: Compare adjacent elements, swap if out of order. Repeat n-1 times. Best: O(n) [already sorted]; Worst/Average: O(n²) Stable, in-place. Good for small/nearly sorted data only. Selection Sort: Find minimum element, put in position 0. Find next min, put in position 1. Etc. Always O(n²) regardless of input. Not stable. In-place. Insertion Sort: Build sorted array one element at a time. Each element inserted in correct position. Best: O(n); Worst/Average: O(n²). Stable. Good for small or nearly-sorted arrays. Quick Sort: Pick pivot. Partition: elements < pivot go left, > pivot go right. Recurse. Average: O(n log n); Worst: O(n²) (sorted array with poor pivot choice) In-place (O(log n) stack space). Not stable. Merge Sort: Divide array in half. Sort each half recursively. Merge the sorted halves. Always O(n log n). Requires O(n) extra space. Stable. Best for linked lists and external sorting (data too large for RAM). Linear Search: Check each element one by one. O(n) worst case. Works on unsorted arrays. Binary Search: Requires SORTED array. Compare target with middle. If equal: found. If target < middle: search left half. Else: search right half. O(log n) time. Very efficient for large sorted datasets.

📌 OOP Concepts

4 Pillars of OOP: 1. Encapsulation: binding data + methods into a single unit (class); hiding internal details 2. Abstraction: showing only essential features; hiding implementation (interfaces) 3. Inheritance: new class (derived) acquires properties of existing class (base) 4. 📌 Inheritance Types

Single Inheritance: one derived, one base (A→B) Multilevel: chain (A→B→C; C inherits from B which inherits from A) Multiple: one derived, multiple bases (B,C→D; D inherits from both B and C) Hierarchical: one base, multiple derived (A→B, A→C, A→D) Hybrid: combination of above types Multipath: diamond problem (D inherits from B and C, both inherit from A) Solved using virtual base class: class B : virtual public A

📌 Database Concepts

DBMS: software to create, manage, query databases (MySQL, Oracle, PostgreSQL, SQLite) Advantages over file systems: reduced redundancy, data integrity, concurrent access, security, easy querying, backup/recovery. Data Abstraction Levels: Physical Level: how data is actually stored (files, indexes, B-trees) Logical Level: what data is stored and relationships (schema, tables) View Level: what end-user sees (specific parts of database = views) Data Independence: Physical: change storage without affecting logical schema Logical: change schema without affecting application (views shield users) Data Models: Relational: data in tables (rows/columns) — most common (SQL) Hierarchical: tree structure (one parent per child) Network: graph structure (multiple parents) Object-oriented: objects with inheritance

📌 ER Model & Keys

ER (Entity-Relationship) Model: Entity: real-world object (Student, Course, Employee) Attribute: property of entity (StudentID, Name, Age) Relationship: association between entities (Student ENROLLS IN Course) Strong Entity: has its own key attribute Weak Entity: depends on another entity for identification (OrderItem depends on Order) Cardinality: One-to-One (1:1): one entity relates to exactly one other (Person:Passport) One-to-Many (1:N): one entity relates to many (Department:Employees) Many-to-Many (M:N): requires a separate relationship table (Students:Courses) Types of Keys: Super Key: set of attributes that uniquely identify a tuple (row) Candidate Key: minimal super key (no redundant attributes) Primary Key: chosen candidate key (unique, not null, one per table) Foreign Key: attribute referencing primary key of another table (ensures referential integrity) Composite Key: primary key made of multiple attributes Unique Key: like primary key but allows one NULL

📌 Functional Dependencies & Normal Forms

Functional Dependency (FD): X→Y means value of X determines value of Y Trivial FD: Y ⊆ X (e.g., {A,B}→{A}) Non-trivial FD: Y ⊄ X (actual constraint) Normalization: process of organizing tables to reduce redundancy and anomalies. Anomalies: insertion, deletion, update anomalies. 1NF (First Normal Form): All attributes are atomic (indivisible). No repeating groups or arrays. Each row is unique. Every cell contains single value. 2NF (Second Normal Form): Must be in 1NF PLUS no partial dependencies. Partial dependency: non-prime attribute depends on PART of composite primary key. Fix: split table so each non-key attribute depends on WHOLE primary key. 3NF (Third Normal Form): Must be in 2NF PLUS no transitive dependencies. Transitive: A→B→C where A is primary key, B is non-key, C is non-key. Fix: move B→C to separate table. BCNF (Boyce-Codd Normal Form): Stricter than 3NF. For every FD X→Y, X must be a super key. Handles cases where candidate keys overlap. Order: BCNF is strongest → 3NF → 2NF → 1NF

📌 OS Concepts & Process Management

OS Goals: User goal: convenient to use, reliable, fast System goal: efficient resource utilization Services: process management, memory management, file management, I/O management, security, network, user interface Process: program in execution. Has its own memory space (code, data, stack, heap). Thread: lightweight process — shares memory with parent process. Advantages: faster creation, less memory, better communication. Process States: New → Ready → Running → Waiting → Terminated Running→Waiting: I/O request or event Running→Ready: time slice expired (preemption) Waiting→Ready: I/O completed PCB (Process Control Block): OS data structure for each process. Contains: PID, state, PC (program counter), registers, memory info, open files, priority

📌 CPU Scheduling Algorithms

Scheduling Criteria: CPU Utilization (↑), Throughput (↑), Turnaround Time (↓), Waiting Time (↓), Response Time (↓) FCFS (First Come First Served): Non-preemptive. Process served in arrival order. Con: Convoy effect — short jobs wait behind long ones. High average wait time. SJF (Shortest Job First): Non-preemptive: picks shortest burst time from ready queue. SRTF (preemptive version): preempts if new process has shorter remaining time. Optimal average waiting time. Problem: need to know burst time in advance. Round Robin (RR): Each process gets a time quantum q. If not done, goes back to ready queue. Preemptive. Fair. Good for time-sharing. q too small → too much context switching. q too large → becomes FCFS. Priority Scheduling: Each process has priority number. Highest priority runs first. Starvation problem: low priority may never run. Solution: Aging (gradually increase priority). Multilevel Queue: Ready queue divided into separate queues for different types (foreground/background). Each queue has its own algorithm. Multilevel Feedback Queue: Processes can move between queues based on CPU behavior. Most flexible, most complex. Used in real OS (Linux CFS, Windows).
Scheduling Example — FCFS

Processes: P1(burst=24), P2(burst=3), P3(burst=3), all arrive at t=0 Gantt Chart: |P1(0-24)|P2(24-27)|P3(27-30)| Waiting times: P1=0, P2=24, P3=27 Average waiting time = (0+24+27)/3 = 17 ms (poor!) If SJF order: P2, P3, P1 Waiting: P2=0, P3=3, P1=6 → Average = 3 ms (optimal!)

📌 Synchronization & Deadlocks

Critical Section Problem: Multiple processes access shared resource; only one should be in critical section at a time. Requirements: Mutual Exclusion, Progress, Bounded Waiting Semaphore: integer variable with wait(P) and signal(V) operations (atomic) Counting semaphore: allows multiple processes (counts resources) Binary semaphore (mutex): 0 or 1 (mutual exclusion) Monitor: high-level synchronization construct; encapsulates shared data + procedures. Deadlock: processes permanently waiting for resources held by each other. 4 Necessary Conditions (ALL must hold for deadlock): 1. Mutual Exclusion: resource can't be shared 2. Hold and Wait: process holds one resource, waits for another 3. No Preemption: resource can't be forcibly taken away 4. Circular Wait: P1 waits for P2, P2 waits for P3, ..., Pn waits for P1 Deadlock Handling: Prevention: eliminate one of the 4 conditions Avoidance: Banker's Algorithm (safe state analysis) Detection: Resource Allocation Graph; recovery by process termination/resource preemption Ignorance: Ostrich Algorithm (pretend it doesn't happen — used in practice!)

📌 Memory Management

Overlays: programmer manually loads parts of program (old technique) Swapping: entire process moved to disk temporarily to free memory. Fragmentation: External: free memory exists but not contiguous (fix: compaction) Internal: allocated memory > needed (fix: smaller blocks) Paging: divide physical memory into fixed-size frames; logical memory into pages. No external fragmentation. Page Table maps page number → frame number. Internal fragmentation possible (last page may not be full). Segmentation: divide logical memory into variable-size segments (code, data, stack). Segment Table maps segment → base+limit. External fragmentation possible. Virtual Memory: allows process to be larger than physical RAM. Uses demand paging: pages loaded only when needed. Page Fault: page not in RAM → OS loads from disk (swap space). Page Replacement Algorithms (when no free frame available): FIFO: replace oldest page. Simple. Can suffer Belady's anomaly. LRU (Least Recently Used): replace page not used for longest time. Optimal in practice. Optimal: replace page that won't be used for longest future time. Theoretical, best performance. Thrashing: process spends more time paging than executing. Fix: reduce multiprogramming.

📌 Disk Scheduling & File Management

Disk Scheduling (minimize seek time): FCFS: service requests in arrival order. Fair but poor performance. SSTF (Shortest Seek Time First): go to nearest track first. Risk of starvation. SCAN (Elevator): head moves in one direction, services all, then reverses. C-SCAN: like SCAN but only services in one direction; jumps back to start. File Operations: create, read, write, seek, delete, open, close, rename Access Methods: Sequential: read records in order (tapes) Direct (Random): access any record directly by position Indexed: use index to find record location Directory Structure: Single-level: one directory for all users (conflicts, no organization) Two-level: separate directory per user Tree-structured: hierarchical (Unix/Windows filesystem) Acyclic graph: allows sharing (hard links, symbolic links) General graph: cycles possible (use garbage collection)
