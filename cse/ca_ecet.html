Stored Program Concept (Von Neumann)

Proposed by John von Neumann (1945). Key idea: both program (instructions) and data are stored in the same memory, and instructions are executed sequentially.

  • Instructions are stored in memory as binary numbers
  • CPU fetches instructions from memory one by one
  • CPU executes: Fetch → Decode → Execute cycle
  • Program Counter (PC) holds address of next instruction
  • Instruction Register (IR) holds current instruction being decoded
Von Neumann Bottleneck CPU and memory share the same bus for data and instructions — this limits speed. It's called the Von Neumann bottleneck. Harvard architecture solves this by using separate buses for data and instructions.

02 Fixed Point & Floating Point Number Representations ▶
Fixed Point Representation

The decimal (binary) point is at a fixed position. All bits are used for magnitude + sign.

  • Unsigned: All bits represent magnitude. Range: 0 to 2ⁿ - 1
  • Signed Magnitude: MSB = sign bit (0=+ve, 1=-ve). Range: -(2ⁿ⁻¹-1) to +(2ⁿ⁻¹-1)
  • 1's Complement: Negate by flipping all bits
  • 2's Complement: Negate by flipping bits and adding 1. Most widely used!

Signed Magnitude01011101-(2ⁿ⁻¹-1) to +(2ⁿ⁻¹-1)
1's Complement01011010-(2ⁿ⁻¹-1) to +(2ⁿ⁻¹-1)
2's Complement01011011-2ⁿ⁻¹ to +(2ⁿ⁻¹-1)
2's Complement Trick For 8-bit: range is -128 to +127. Note: -128 has no positive counterpart! 2's complement of 10000000 is still 10000000.

03 Complements (1's and 2's) ▶
r's Complement and (r-1)'s Complement
TypeBinaryDecimal (r=10)How to find
1's Complement (r-1)Flip all bits9's comp = 9999...9 - N0→1, 1→0 for each bit
2's Complement (r)Flip bits + add 110's comp = 10ⁿ - N1's comp + 1
Example: Find 2's complement of 10110
Step 1 — 1's complement: 01001  (flip all bits)
Step 2 — Add 1:          01001
                       +     1
                        ──────
                         01010  ← 2's complement of 10110

Shortcut: From rightmost bit, keep bits until first 1 (inclusive), then flip rest
10110 → keep '0', keep '1', flip rest → 0 1 0 1 0 → 01010 ✓
Subtraction using Complements
To compute A - B using 2's complement:
  = A + (2's complement of B)
  If carry generated → ignore carry, result is positive
  If no carry → result is negative (take 2's complement of result)

Example: 1010 - 0110 (i.e., 10 - 6 = 4)
2's comp of 0110 = 1010
    1010
  + 1010
  ──────
  10100  → carry=1, ignore it → 0100 = 4 ✓
Why 2's Complement is Preferred • Only ONE representation of zero (unlike 1's complement which has +0 and -0)
• Subtraction becomes addition → simpler hardware
• Arithmetic carry works naturally

Virtual Memory

Virtual memory gives programs the illusion of having more RAM than physically exists by using disk space as extension of RAM.

  • Programs use virtual addresses; hardware/OS maps them to physical addresses
  • Uses a Page Table to map virtual pages to physical frames
  • Page fault: accessing a page not in RAM → OS loads it from disk
  • TLB (Translation Lookaside Buffer): fast cache for page table entries
  • Allows multiprogramming (multiple processes share RAM)
TermMeaning

06 Cache Memory & Associative Memory ▶
Cache Memory

Cache is a small, fast memory between CPU and RAM. It stores frequently accessed data/instructions.

  • Hit: Data found in cache → fast access
  • Miss: Data NOT in cache → go to RAM (slow)
  • Hit ratio = Hits / (Hits + Misses)
  • Average access time = h × Tc + (1-h) × Tm (h = hit ratio, Tc = cache time, Tm = main memory time)
MappingHow it WorksAdvantageDisadvantage
Direct MappingEach RAM block maps to exactly ONE cache line (index = block# mod cache size)Simple, fastHigh conflict misses
Fully AssociativeAny RAM block can go to ANY cache lineNo conflict missesExpensive, slow search
Set AssociativeCache divided into sets; block maps to a set, can go to any line in setBalance of bothMore complex
Cache Replacement Policies LRU (Least Recently Used) – most popular | FIFO (First In First Out) | LFU (Least Frequently Used) | Random
Associative Memory (Content Addressable Memory – CAM)

Unlike normal RAM (accessed by address), associative memory is accessed by content (data). Parallel search in all locations simultaneously.

  • Each cell has both storage and comparison logic
  • A search key is applied; all locations compared simultaneously
  • Returns all matches in one cycle
  • Used in: TLB, cache tags, network routers
  • More expensive than RAM but much faster for search operations
Key Difference RAM: given address → returns data | CAM/Associative: given data → returns matching address(es)

07 I/O Organization & Modes of Data Transfer ▶
Three Modes of I/O Data Transfer
ModeHow it worksCPU InvolvementSpeed
Programmed I/OCPU continuously polls (checks) device status in a loop (busy-waiting)100% — wastes CPUSlowest
Interrupt-Driven I/OCPU sends command, does other work; device sends interrupt when readyOnly during interrupt handlingMedium
DMA (Direct Memory Access)DMA controller transfers data directly between device and memory; CPU only sets up transferMinimal (setup + completion)Fastest
Detailed: Each Mode
Programmed I/O (Polling) CPU sends command to I/O device, then keeps checking (polling) a status register in a loop until device is ready. Very wasteful — CPU does nothing useful while waiting (busy-wait loop).
Interrupt-Driven I/O CPU sends command, continues doing other work. When I/O is done, device sends an INTERRUPT signal. CPU saves state, runs Interrupt Service Routine (ISR), then resumes. More efficient than polling. Types: maskable (can be disabled) and non-maskable (NMI, cannot be disabled).
DMA (Direct Memory Access) CPU programs the DMA controller (source address, destination, byte count, direction). DMA controller handles entire transfer directly between I/O device and RAM — CPU is free! When done, DMA sends interrupt. Uses cycle stealing (temporarily takes bus from CPU) or burst mode. Best for large data transfers (disk, network, audio).

Bus Arbitration

When multiple devices want the bus simultaneously, arbitration decides who gets it:

  • Daisy Chaining: Priority determined by physical position on chain. Simple but low-priority devices may starve.
  • Centralized Parallel: All devices connected to central arbiter. Fast but complex.
  • Distributed: Each device has its own arbitration logic. No single point of failure.

09 Pipeline, Parallel Processing & Vector Processing ▶
Instruction Pipeline

Pipelining overlaps execution of multiple instructions — like an assembly line. A classic 5-stage pipeline:

Stage: IF ID EX MEM WB Instr 1: ──█───────█───────█───────█───────█ Instr 2: ──█───────█───────█───────█───────█ Instr 3: ──█───────█───────█───────█───────█ t1 t2 t3 t4 t5 t6 t7 IF = Instruction Fetch | ID = Instruction Decode EX = Execute | MEM = Memory Access | WB = Write Back
  • Without pipeline: k stages × n instructions = k×n cycles
  • With pipeline: k + (n-1) cycles ≈ n cycles for large n
  • Speedup = k (number of stages) for ideal case
Pipeline Hazards (Problems) Structural hazard: resource conflict (two instructions need same hardware) | Data hazard: instruction depends on result of previous (RAW, WAR, WAW) | Control hazard: branch instructions — correct path not known yet
Solutions to Hazards • Data forwarding/bypassing (data hazard) | • Branch prediction (control hazard) | • Pipeline stall/bubble insertion | • Out-of-order execution
Arithmetic Pipeline

Used to pipeline arithmetic operations like floating-point addition. Example: FP Add pipeline:

Stage 1: Compare exponents
Stage 2: Align mantissas (right-shift smaller)
Stage 3: Add mantissas
Stage 4: Normalize result
Vector Processing

Operates on entire arrays (vectors) of data in one instruction, rather than one element at a time.

  • Single vector instruction replaces a loop: C = A + B (where A, B are arrays)
  • Uses vector registers that hold multiple values
  • Heavily used in: scientific computing, graphics, multimedia
  • Examples: SIMD (SSE, AVX in x86), GPU processing

Flynn's Classification (1966)

Classifies computer architectures based on number of Instruction Streams (IS) and Data Streams (DS):

ClassFull FormDescriptionExample
SISDSingle Instruction, Single DataClassical Von Neumann — one instruction on one data at a timeTraditional single-core CPU
SIMDSingle Instruction, Multiple DataSame instruction applied to multiple data simultaneouslyVector processors, GPUs, SSE/AVX
MISDMultiple Instructions, Single DataMultiple instructions on same data (rare in practice)Fault-tolerant systems, space shuttle
MIMDMultiple Instructions, Multiple DataMultiple processors each executing different instructions on different dataMulti-core CPUs, clusters, distributed systems
Exam Memory Tip SISD = 1 processor (traditional) | SIMD = GPU / vector | MISD = very rare / theoretical | MIMD = modern multi-core systems
